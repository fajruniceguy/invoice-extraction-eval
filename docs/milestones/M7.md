# M7: API, batching, cost and latency

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#M7

## Goal
`uvicorn` serves `/health`, `/extract` (one document from uploaded files) and `/extract/batch` (many documents,
bounded concurrency); every request leaves a token/cost/latency log line; `scripts/extract.py` can run documents
concurrently; and the scorecard reports cost per document and latency p50/p95, overall and by slice.

## Scope
- `docextract/extract/concurrent.py`: `run_bounded(items, worker, *, concurrency, skip, skipped)`: results in input
  order, at most `concurrency` workers running, `skip()` checked after the semaphore is won (the cost-cap stop), a
  failing worker propagates and cancels the rest (`asyncio.TaskGroup`).
- `extract/runner.py`: the per-document part of `_extract_one` becomes a public `extract_record(doc_id, pages, ...) ->
  (DocRecord, hit_cap)` used by the runner AND the API, so their records are identical; `run_extraction(...,
  concurrency=1)` runs through `run_bounded`; `RunRecord.concurrency: int = 1` (an old run.json still parses, and
  `compare`'s "what differs" is unaffected). Records are written as each document finishes, `on_record` fires in
  completion order, `statuses` keeps the selection order. `concurrency=1` gives today's records and order.
- `scripts/extract.py --concurrency N` (integer >= 1, otherwise exit 2); the other exit codes are unchanged.
- `docextract/calllog.py`: `CallLog(path | None)` with `log(record, request_id=, route=, index=)`: one JSON line per
  document request (request id, route, index, status, model, pages, input and billable output tokens, cost paid and
  avoided, cache hit, latency, attempts, repairs; no file name, no content) to the `docextract.calls` logger and, when a
  path is set, appended to a JSONL file.
- `docextract/api/uploads.py`: `pages_from_uploads(files, workdir, *, max_pages, page_range)` turns uploaded bytes into
  page files with the same `load_pages` + `store_pages` + `IngestSettings()` ingestion uses and no redaction, so pages are
  byte-identical to ingested ones (same response-cache keys). Client file names never become paths (written as
  `f0.bin`...), PDFs are page-counted before rendering, a temp dir is removed afterwards; `UploadError` subclasses for
  unreadable files and too many pages.
- `docextract/api/app.py`: `create_app(settings=None, *, client=None)` (no import-time configuration); the lifespan owns
  one `OpenAICompatClient`, one process-wide `asyncio.Semaphore(API_CONCURRENCY)` and the `CallLog`; page rendering runs
  in a thread. Routes, with an `X-Request-Id` header on every answer:
  - `GET /health`: status, model, concurrency, budget spent/limit/exceeded, call count. No secrets.
  - `POST /extract`: multipart `files` (one or more, the pages/photos of ONE document, in order), optional form
    `page_range` (a single PDF) and `doc_id`; answers a `DocRecord` (`?compact=true` drops `raw_text`, `parsed`,
    `repair_history`). Errors: 400 unreadable file or no files, 401 bad token, 413 file too large, 422 too many pages
    (`LLM_MAX_PAGES`), 502 provider or parse failure (the body carries the failed record), 503 `budget_exceeded`.
  - `POST /extract/batch`: multipart `files`, each file one document, at most `API_MAX_BATCH` (else 413), processed
    concurrently, answered synchronously with 200: `{"run": {documents, ok, failed, refused, not_run, repairs, tokens,
    cost paid and avoided, cached_calls, stopped, wall_ms}, "documents": [DocRecord...]}` in upload order. A file that
    cannot be read is a `refused` record, a provider failure `failed`, and a cost-cap stop leaves the rest `not_run`
    with `run.stopped = "cost_cap"`.
  - `API_TOKEN`, when set, is required as `Authorization: Bearer` on `/extract*` (constant-time compare); unset = open.
- `config.py`: `api_concurrency` (4), `api_max_batch` (20), `api_max_upload_mb` (25, per file), `api_token` (secret,
  none), `call_log_path` (none); `.env.example` lists them (API_CONCURRENCY, API_MAX_BATCH, API_MAX_UPLOAD_MB,
  API_TOKEN, CALL_LOG_PATH).
- `evalkit/perf.py`: `percentile` (nearest-rank), `PerfStats` with `from_records`, `perf_by_slice`. `scorecard.py`:
  `Scorecard.perf` and `perf_slices` (new fields with defaults), a "Cost and latency" section in `scorecard.md` and keys
  in `scorecard.json`; `scripts/score.py` prints one cost/latency line. The numbers cover every document of the run that
  was attempted (status ok or failed), labeled or not. Latency percentiles are over LIVE ok calls only (a cache replay
  takes 0 ms and would flatter p50). Cost is shown paid and at list price (paid + avoided).
- Dependencies `fastapi`, `uvicorn`, `python-multipart` in the main group (`python -m uv add`, updates `uv.lock`).
  Serve with `python -m uv run uvicorn --factory docextract.api.app:create_app`.
- Retry with exponential backoff already exists in the client: M7 adds a test that the API answers a retried 429 as one
  successful response, and no new retry code.

## Out of scope
- Async jobs and polling, by-reference batch (doc_ids), a metrics endpoint (N4), per-caller rate limiting, persistence
  of uploads, streaming.
- Docker and compose (M9), the resolution sweep (M8), cost/latency deltas inside `compare`.
- Any labeling or data work (the user's).

## Acceptance criteria
Offline and deterministic unless marked.
1. `python -m uv run pytest -q tests/test_concurrent.py tests/test_extract_runner.py` -> all pass. Covers: at most N
   workers at once (measured), order kept, `skip` honored after the cost cap, a raising worker cancels the rest;
   `concurrency=1` records equal the old sequential ones; `concurrency=3` against the delayed fake server gives the same
   records as 1 in less wall time; a cost-cap stop with concurrency leaves unstarted documents `not_run`;
   `run.json.concurrency` recorded.
2. `python -m uv run pytest -q -m slow tests/test_extract_script.py` -> passes: `--concurrency 2` end to end;
   `--concurrency 0` and `abc` exit 2.
3. `python -m uv run pytest -q tests/test_perf.py tests/test_scorecard.py` -> all pass. Covers: nearest-rank percentiles
   on literal lists (1, 2, 3 and 20 values), cache replays excluded from latency but not from list-price cost, failed
   documents counted in cost, refused and not_run not counted, slices, `n/a` with no live call, byte-identical JSON and
   markdown on a second call.
4. `python -m uv run pytest -q tests/test_calllog.py` -> all pass. Covers: one line per request with the documented keys,
   valid JSON, no file name or content, appending from two writers, `None` path = logger only.
5. `python -m uv run pytest -q tests/test_uploads.py` -> all pass. Covers: an uploaded PDF, PNG and JPEG yields pages
   byte-identical to `ingest_document`'s; garbage bytes, a 21-page PDF over `LLM_MAX_PAGES=20`, an oversize file and a
   hostile file name are refused without writing outside the temp dir; the temp dir is gone afterwards.
6. `python -m uv run pytest -q tests/test_api.py` -> all pass. Covers: `/health` (no secrets); `/extract` happy path (PDF
   and PNG, `?compact`), a multi-file document, each error code above, the token when set, a retried 429 -> one 200, a
   record equal to the CLI's for the same pages; `/extract/batch`: order kept, a bad file `refused` while the others
   succeed, concurrency never above `API_CONCURRENCY` (fake-server arrival times), a cap stop -> `not_run` + `stopped`,
   more than `API_MAX_BATCH` -> 413; every request logged; `/health` answers while a render is running.
7. `python -m uv run pytest -q -m slow tests/test_api_server.py` -> passes: `python -m uvicorn --factory
   docextract.api.app:create_app` in a subprocess against the fake LLM answers `/health` and one `/extract`.
8. `python -m uv run pytest -q -m "slow or not slow"` -> all pass; `python -m uv run ruff check` -> `All checks passed!`
9. `python -m uv run python scripts/score.py outputs/runs/m6-degraded` (and `m4-live`, `m6-baseline`) -> prints the
   cost/latency line and `scorecard.md` has "Cost and latency" overall and per slice: m6-degraded latency p50 43.2 s / p95
   48.3 s over 3 live calls; m4-live "no live calls" and a list-price cost per document of $0.0380 (its avoided
   $0.1141 / 3).
10. [COSTS $0 expected: the answers replay from the response cache; any page that misses it costs about $0.04 per
    document, at most $0.15 and 3 requests; run only after approval] Start the server; `curl -F files=@cons_001.pdf
    /extract`, then the three constructed PDFs to `/extract/batch`: the records equal `outputs/runs/m6-baseline`'s
    (validated output), cost paid is $0, and the call log has 4 lines. The commands and output go into

## Risks
- Parallel calls burn the Gemini per-minute and per-day quota and trigger 503s sooner -> `API_CONCURRENCY` is a
  setting (default 4) with a warning in `.env.example`; the demo uses 1-3; 503 retries stay the client's.
- Cost-cap overshoot grows to concurrency x one call -> documented in CLAUDE.md and tested (unstarted documents are
  `not_run`).
- Refactoring `_extract_one` touches the production path -> `concurrency=1` must give records identical to today's
  (golden comparison in the tests) plus a mutation pass.
- PDF rendering blocks the event loop -> `asyncio.to_thread`, with a test that `/health` answers meanwhile.
- Hostile uploads (huge PDFs, pixel bombs, odd names) -> page count first, size cap, Pillow's pixel limit left on, names
  never used as paths.
- The scorecard change alters M5's output -> only additive keys and sections; existing assertions stay.
- New dependencies on Windows / Python 3.11 -> `uv add` first; tests prove an import and a real uvicorn start.

## Deviations from roadmap
- "Backoff": the client already has it; M7 proves the API surfaces it. "Per-call logging": one line per document request
  (with `attempts` and `repairs`), not one per HTTP attempt.
- Latency percentiles exclude cache replays (stated in the report).
- `/extract/batch` takes uploads (one file per document) and answers synchronously (decided with the user, who also chose
  `--concurrency` for the runner).
