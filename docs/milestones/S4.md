# S4: Hallucination probe set: fields digitally erased, the expected answer is "absent" or "abstained"

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#S4; scope (constructed invoices only) approved by the owner on 2026-10-09

## Goal
A measured, separately reported hallucination rate: the share of fields that were erased from a copy of a document and that the
system still answered with a value. The brief's "must not hallucinate values that are not there" gets a number that does not
depend on a human label being right, because here the truth is known by construction: the field is not on the page any more.

## Design
- **Sources**: the three constructed invoices (cons_001 classic, cons_002 modern, cons_003 compact). They are regenerated
  deterministically from `evalkit.construct` (same seed, same `Invoice`), so a probe is a copy of a document the dataset already
  has, and no real page is read or viewed. The regenerated PDFs must be byte-identical to `data/private/raw/constructed/` when
  those exist.
- **Erasure**: render each PDF page exactly as ingestion does (`load_pages`, 200 dpi, cap 2400), find every occurrence of the
  erased VALUE in the PDF text layer (pdfium text search; the printed label next to it, such as "NPWP:" or "Pembeli:", stays,
  so the page still invites an answer), and paint over it with the colour sampled around it (the modern layout prints its
  header in white on a dark band, so white would not do). Dropping a page removes the last page, where subtotal, discount,
  tax and total are printed. The erased pages are saved as PNG and ingested by the real `ingest_document`, so a probe is stored
  exactly like any other document (`data/probes/pages/<id>/pN.png` + `ingest.json`).
- **Labels**: derived from the same `Invoice`: the erased fields are `null` (absent); a dropped last page nulls subtotal,
  discount, tax and total and keeps only the rows on the remaining pages; fields that the remaining pages no longer decide
  (the currency, when "Rp" was printed only in the totals) are `__unlabeled__`, never guessed.
- **The probes** (9, plus 3 controls = the unmodified documents, re-ingested):

  | id | source | what is taken away |
  | --- | --- | --- |
  | p01 | cons_001 | document_number (every occurrence: the header and each continuation page) |
  | p02 | cons_001 | vendor_tax_id (the value; "NPWP:" stays) |
  | p03 | cons_002 | document_date |
  | p04 | cons_002 | vendor_name and vendor_address (the white-on-dark header block) |
  | p05 | cons_003 | buyer_name |
  | p06 | cons_003 | due_date and payment_method |
  | p07 | cons_001 | the last page (the totals block) |
  | p08 | cons_002 | the values of subtotal, tax and total (their labels stay; the rows are all still there) |
  | p09 | cons_003 | the last page |
  | c01 c02 c03 | cons_001..003 | nothing: the controls |

  19 erased fields in the 9 probes: 1+1+1+2+1+2 = 8 by erasure, 4 for each dropped last page of cons_001 and cons_003 (a discount
  is printed there), 3 for p08. The generator writes the exact count. p08 is the sharp one: the model can compute the three amounts from the rows, and
  `absent` means "the document does not state it", so a computed value is a hallucination by the schema's own definition.
- **Scoring** (read after the run, no threshold, nothing gates): for each erased field the returned (validated) status is
  `absent` (right), `abstained` (also right: the expected output is abstention) or `extracted` (a hallucination). Reported for
  what the system returned AND for the model's own answer before the validators, with an exact (Clopper-Pearson) 95%
  interval, because 20 fields is a small sample. Every extracted case is split into "the value that was erased" (recovered or
  computed, which still breaks the schema's rule) and "another value" (invented). Also reported: whether the CONTROL read
  that field right (an erased case where the control was wrong anyway tells less), the accuracy of the fields that were NOT
  erased (the guard must not simply answer nothing), and the rows invented for a dropped page.
- **Prediction, written before the run, not a target**: the totals probe (p08) will show the highest rate, because the amounts
  are derivable; the header probes (p01-p06) the lowest; the dropped-page probes will mostly be right on the totals but may
  invent rows. If the result differs, the reading says so.

## Acceptance criteria
Offline and deterministic unless marked.
1. `python -m uv run pytest -q tests/test_probes.py` -> all pass: the label derivation for every probe kind; the erase finds all
   occurrences of a value (including a number repeated on continuation pages) and refuses a value it cannot find; the erased box
   was inked before and is one flat colour after; the fill is the surrounding colour (a white-on-dark header stays dark);
   `drop_last_page` keeps the earlier pages byte-identical; the controls' pages are byte-identical to the dataset's; a second
   generation is byte-identical; the report counts (hand-worked world), the exact interval, the recovered/invented split.
2. `python -m uv run python scripts/make_probes.py` -> writes `data/probes/`; `--check` afterwards exits 0 ("identical");
   the stored controls equal `data/pages/cons_00N/p*.png` by hash, and the dropped-page probes' remaining pages equal the
   source's.
3. `python -m uv run python scripts/extract.py --split test --dry-run --manifest data/probes/manifest.csv --pages-dir
   data/probes/pages --ground-truth-dir data/probes/labels` -> 12 documents "would extract", 0 refused.
4. Mutation pass on `probes.py` (`tests/mutants/probes.py`): every mutant killed.
5. [COSTS MONEY, about $0.10 (cons_001/002 controls are cache hits; estimate from `test-g1`: $0.005-0.011 per constructed
   document; cap $0.50 from `.env`), only after the owner approves] `extract.py --split test --manifest ... --pages-dir ...
   --ground-truth-dir ... --run-id probe-s4`, then `score.py` with the same paths, then `probe_report.py outputs/runs/probe-s4`
   -> `docs/eval/hallucination_probe.md`; the run folder is copied to `results/probes/probe-s4/`.
6. `python -m uv run pytest -q -m "slow or not slow"` and `python -m uv run ruff check` -> green (the known flaky
   `test_mutation_check` is rerun alone before it is called a failure).
7. `git status`: nothing changed under `ground_truth/`, `data/pages/`, `data/manifest.csv`, `results/test-*`.

## Risks
- A text-search rectangle may not cover every glyph (descenders, tight fonts) -> the erased box is padded and checked for one flat
  colour; the probe is refused when it is not.
- A value string may also occur somewhere it should not be erased (a money value inside a longer number) -> the generator
  counts the matches, restricts money values to the last page, and refuses the probe when the count is not what the layout
  predicts.
- Clean synthetic pages are easier than real ones: the rate is a floor, not an estimate for the real documents. Said in the
  report; real-document probes are the follow-up.
- 20 erased fields is a small sample -> exact intervals are reported and no comparison between probe kinds is called a finding.
- A drop-page probe's label for rows is the remaining rows only; a model that reads page 2 of a 3-page document as complete is
  not wrong -> `row_spurious` there is reported as invented rows, not as an error class of its own.

## Deviations from roadmap
- The roadmap says "5-8 copies of documents": 9 probes plus 3 controls here, because each field kind (header text, a date, a tax
  id, a totals block, a page) is its own failure and the controls separate "could not read it" from "was never there".
- Constructed documents only, decided with the owner; the roadmap's "documents" is read as "any of the dataset's documents".
