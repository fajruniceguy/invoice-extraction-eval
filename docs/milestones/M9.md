# M9: Docker (api + eval services), an eval client that goes through the API, committed run artifacts

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#M9 (and S6: the offline re-score of committed predictions that E1 deferred to M9)

## Goal
From a clean clone with only `.env` filled in, `docker compose up` serves the API and `docker compose run --rm eval`
scores the test split THROUGH that API, writing the run and its scorecard to `./outputs`. One real run's artifacts are
committed under `results/`, and CI re-scores them offline with no key.

## Scope
- `Dockerfile` (one image for both services): `python:3.11-slim`, uv with `--frozen`, runtime dependencies only (no dev,
  degrade or tools groups), non-root user. `.env`, `data/private/`, `outputs/`, `.git/`, `.venv/` are never copied in
  (`.dockerignore`). The image carries `src/`, `scripts/`, `data/manifest.csv`, `data/pages/`, `ground_truth/`, so the
  eval runs out of the box.
- `docker-compose.yml`:
  - `api`: `uvicorn --factory docextract.api.app:create_app`, `env_file: .env` (a clean clone needs only that file),
    `./outputs` mounted (response cache and call log survive), port 8000, healthcheck on `GET /health`.
  - `eval`: same image, `depends_on: api (service_healthy)`, no model key, `./outputs` mounted, runs
    `scripts/eval_api.py`, default selection `--split test`, API URL `http://api:8000`.
- `scripts/eval_api.py` (the eval client): selects documents (`--split` | `--doc`), applies the blind rule itself
  (`runner.blind_refusal`: the server does not know the labels) and `stored_pages`, POSTs each document's stored pages to
  `POST /extract` (`files` in page order, `doc_id`), `--concurrency N` documents at a time, and writes the SAME run
  folder `extract.py` writes (`docs/<id>.json`, `run.json`), then scores it (`score_run`) into `<run>/score/`. Options:
  `--api-url`, `--token` / `API_TOKEN`, `--run-id`, `--runs-dir`, `--no-score`, `--dry-run`, plus the dataset path
  options of `extract.py`. Exit codes as `extract.py`: 0 all ok, 1 a document failed or was refused, 2 bad arguments /
  API unreachable / empty selection, 3 the API's cost cap stopped the run (503 `budget_exceeded`; documents not started
  are `not_run`). It never reads `.env` and holds no model key.
- `GET /health` additionally reports `prompt_sha256`, `schema_sha256`, `endpoint` and the result-affecting settings
  (the same dict `run.json` records), so `run.json` describes what the SERVER used. Additive: existing keys unchanged.
- `scripts/promote_run.py RUN_DIR`: copies a finished, scored run to `results/<run_id>/` (`run.json`, `docs/`,
  `score/`). Refuses a run with no `score/`, one that is `stopped`, one with a `not_run`/`failed` document unless
  `--allow-incomplete`, an existing target, and anything the secret scanner's key shapes match. Writes nothing else.
- `results/<run_id>/` with the real run of the test split, and `results/README.md` (the command, model, date, cost, the
  prompt hash, and the known caveat: the grounding flaw in `docs/eval/failure_analysis.md` is NOT fixed in this run).
- CI (`.github/workflows/ci.yml`): a step that re-scores every `results/*` run offline into a temp dir and fails if the
  scorecard differs from the committed one. Fields that legitimately change are ignored: git SHA / dirty, scoring time.
- Docs: DEVLOG entry; CLAUDE.md gets one short "Docker and eval through the API" section and the new files in Layout and
  Commands.

## Out of scope
- Fixing the grounding flaw or any change in `validate/`, `confidence/`, `extract/`, or the scoring in `evalkit/`.
- A Docker job in CI (the CI runner is Windows and cannot run Linux containers), async jobs, GPU / Ollama, a registry push.
- README, ARCHITECTURE and the agentic note (M10).
- Committing the response cache or anything under `outputs/`.

## Acceptance criteria
Offline and deterministic unless marked.
1. `python -m uv run pytest -q tests/test_eval_api.py` -> all pass. Runs the real client against the in-process API (ASGI
   transport) with the fake LLM. Covers: a run folder that `score_run` accepts and that has the shape of `extract.py`'s;
   pages sent in order and byte-identical to the stored ones; a BLIND document without a label is refused with ZERO
   requests; a provider failure is `failed` and the run goes on; the cost cap gives exit 3 and `not_run` for the rest;
   an unreachable API gives exit 2; a bearer token is sent; `run.json` records the server's hashes and settings.
2. `python -m uv run pytest -q tests/test_api.py tests/test_promote_run.py` -> all pass: `/health` fields; promote refuses
   an unscored, stopped, incomplete or already-promoted run and copies a good one byte for byte.
3. `python -m uv run pytest -q tests/test_docker_files.py` -> all pass: the Dockerfile uses a pinned Python 3.11 base, a
   frozen uv sync, a non-root user, copies no `.env`; `.dockerignore` excludes `.env`, `data/private`, `outputs`, `.git`,
   `.venv`; compose has `api` (healthcheck, `env_file`) and `eval` (`depends_on` healthy, no `env_file`, no model key);
   a fresh runtime-only install of the image's dependency set imports `docextract` and `evalkit`.
4. `python -m uv run python scripts/score.py results/<run_id> --out <tmp>` -> the scorecard equals the committed one except
   git SHA / dirty and time; and the CI comparison step, run locally, exits 0. A one-character edit of a committed
   `docs/<id>.json` makes it exit non-zero (a test).
5. [Docker, no model cost, needs network for the base image and wheels] `docker compose build`; start
   `python tests/fakes/fake_llm.py 8765` on the host; `LLM_BASE_URL=http://host.docker.internal:8765/v1 LLM_MODEL=fake
   LLM_API_KEY=x` in a throwaway env file; `docker compose up -d --wait` -> `api` healthy; `docker compose run --rm eval
   --doc cons_001` -> exit 0 and `outputs/runs/<id>/score/scorecard.md` exists. Then `docker compose down`.
6. [COSTS MONEY, about $0.10-0.25 for 25 documents at the $0.50 cap; run only after approval] `docker compose up -d --wait`
   then `docker compose run --rm eval --run-id test-final` with the real `.env` -> 25 documents attempted, scorecard
   written. `scripts/promote_run.py outputs/runs/test-final` -> `results/test-final/`, then criterion 4 on it.
7. `python tools/secret_scan.py --worktree` (with `results/` present) -> clean.
8. `python -m uv run pytest -q -m "slow or not slow"` and `python -m uv run ruff check` -> green.

## Risks
- A clean clone has an empty response cache, so the first eval run spends real money -> the compose default carries the
  server's `MAX_RUN_COST_USD`; the README (M10) and `results/README.md` say so.
- `env_file: .env` also hands the pre-labeler key to the API container, which does not use it -> accepted so a clean
  clone needs only `.env`; the key is not written into the image, the eval container never receives it.
- The server's cost cap is a process-lifetime budget: a second eval against the same container may start already
  capped -> documented; `docker compose restart api` resets it.
- Model output on the test split is nondeterministic: the committed run is one sample (noise rules in `docs/eval/noise.md`
  apply) and is labelled as such.
- Docker bind mounts on Windows are slow and can change line endings -> the eval writes only inside the container's
  mounted `outputs/`; committed files are produced by the host-side `promote_run.py`.
- The model's `raw_text` in committed records echoes (redacted) page content -> pages are already redacted, and
  `promote_run.py` plus the secret scan check for key shapes; the owner reviews `results/` before pushing.

## Deviations from roadmap
- The roadmap says "`docker compose run --rm eval` hits the API", but no client that goes through the API existed
  (`extract.py` calls the model in-process): `scripts/eval_api.py` is new code, not just packaging.
- "Real run artifacts committed" goes to `results/`, not `outputs/` (which is gitignored by design).
- The frozen test-split run is made BEFORE the grounding decision (decided with the owner); its scorecard is therefore the
  baseline that a later fix is compared against with `compare.py`.
