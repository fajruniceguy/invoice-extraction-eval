# E1: Secret scan (a Claude Code hook), a mutation-check tool and skill, `.env.example`, CI

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#M10 (custom extension, `.env.example`), S6 (CI), and the submission checklist in CLAUDE.md

## Goal
A commit that would add a secret is stopped before it happens, the mutation testing used all through this project is a
committed tool and skill, a clean `.env.example` exists, and CI runs the repository's own gate.

## Scope
- `tools/secret_scan.py` (stdlib only, no project imports, so a hook can run it with any Python). Scans ADDED lines only.
  Rules: well-known key shapes (`sk-...`, `AIza...`, `ghp_`/`github_pat_`, `AKIA...`, Slack `xox*-`, PEM private key
  headers); an assignment to a name containing KEY, TOKEN, SECRET or PASSWORD with a value of 16+ characters that is not a
  placeholder (placeholders: contains `your`, `example`, `placeholder`, `changeme`, `xxxx`, `<`, `...`, `${`, or one
  repeated character); and a staged `.env` or `*.env` file other than `.env.example`. Findings print the file (or
  commit), the line number, the rule and a MASKED excerpt: the value itself is never printed. Modes: `--staged` (the
  index), `--history` (every commit of every ref), `--env-values` (reads the real `.env` in memory, takes the values of
  the sensitive names, and searches the whole history for each; prints only the variable NAME and the commit). Exit 0
  clean, 1 findings, 2 usage or git error.
- `.claude/hooks/pre_commit_secret_scan.py` and `.claude/settings.json`: a PreToolUse hook on Bash. When the command is a
  `git commit`, it runs the staged scan; findings exit 2 with the report on stderr, which blocks the commit and shows
  Claude why. Every other command passes untouched. It exists because a real key was nearly committed in `.env.example`
  on 2026-10-08.
- `tools/mutation_check.py` and `.claude/skills/mutation-check/SKILL.md`: the mutation procedure used in every milestone,
  as a tool. A mutants file (`MUTANTS = [(path, tests, name, old, new), ...]`) is run against an ISOLATED COPY of the
  repository (a mutation pass edits the files a running Streamlit app imports; that bit us once), after a baseline run
  that must be green (a harness that cannot run the tests reports every mutant as killed; that bit us too), and a mutant
  whose `old` text does not occur exactly once is refused. Output: killed / SURVIVED per mutant, exit 1 on survivors.
- `.env.example`: placeholders only, current defaults (DeepSeek V4 Flash Vision through Command Code, `json_object`,
  effort `medium`, official list prices with the peak/off-peak note), every variable the code reads, and the alternatives
  that were tried (GLM, Gemini, Ollama) in one line each. No value in it looks like a key.
- `.github/workflows/ci.yml`: on push and pull request, `windows-latest` (the only platform the suite has run on), Python
  3.11, `uv sync`, `ruff check`, `pytest -q -m "slow or not slow"`, and `tools/secret_scan.py --history`. The offline
  re-score of committed predictions is added with M9, when those exist.
- Run `--history` and `--env-values` on this repository now and report the result.

## Out of scope
- M9 (Docker, replay, committed run artifacts), any change to `src/docextract` or `src/evalkit`, fixing the grounding
  flaw, a git `pre-commit` installer, running CI on GitHub (not possible from here), rotating a key (the owner's call
  if a scan finds one), reading `.env` for any purpose except the in-memory comparison above.

## Acceptance criteria
Offline and deterministic.
1. `python -m uv run pytest -q tests/test_secret_scan.py tests/test_mutation_check.py tests/test_ci_and_env_example.py`
   -> all pass. Fake keys in tests are built at runtime (`"sk-" + "a" * 30`) so the test files themselves are clean.
   Covered: each rule fires on a fake secret and is silent on a placeholder; only added lines count; a staged `.env` is
   refused and `.env.example` is not; the report never contains the value; `--history` finds a key added and removed in an
   earlier commit; `--env-values` finds a real value in history and prints only its name; the hook blocks a `git commit`
   with a staged fake key (exit 2), lets a clean commit and every non-commit command through; the mutation tool kills a
   real mutant, reports a survivor, refuses a baseline that fails and a mutant that matches twice, and never edits the
   original tree.
2. `.env.example` loads through `Settings` with its placeholders, contains every variable name the code reads, and passes
   the scanner; `ci.yml` parses and runs exactly the gate commands.
3. `python tools/secret_scan.py --history` and `python tools/secret_scan.py --env-values` on this repository -> exit 0,
   or the findings reported to the owner before anything else is done.
4. `python -m uv run pytest -q -m "slow or not slow"` and `python -m uv run ruff check` -> green.
5. Mutation pass over `secret_scan.py` with the new tool itself (a mutant of each rule is killed).

## Risks
- A scanner that cries wolf gets disabled -> placeholders are recognized, only added lines count, tests include the
  repository's own `.env.example` and the previous `.env.example` from history.
- The hook only runs inside Claude Code -> the same scanner is the first CI job, so a commit made outside it is caught
  before it can be merged; it does not replace rotating a key that was ever pushed.
- CI is written, not run (no runner here) and the suite has only run on Windows -> `windows-latest`, and the first CI run
  is a checkpoint for the owner.
- `--env-values` reads the real `.env` -> in memory only, names printed never values, covered by a test that asserts the
  value is absent from stdout and stderr.

## Deviations from roadmap
- The roadmap has no "tool" for mutation checking; it is added because it is the extension actually used throughout.
