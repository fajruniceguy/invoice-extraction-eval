# G1: Grounding fix, option (a): an ambiguous number that contains the model's value is soft, not hard

Status: spec (written before code; not edited after approval)
Roadmap ref: none (found by S1, `docs/eval/failure_analysis.md`, option (a)); scope and order approved by the owner on 2026-10-09

## Goal
A correct money value is no longer withheld because its own quote prints an AMBIGUOUS number (`208,179`, `84.000`) when the
model's value is one of the two readings the normalizer offered. The value is kept with a capped confidence and a soft reason
code; a value that matches no reading stays a hard contradiction. The no-guessing rule is untouched: the normalizer still
refuses to pick a reading, and the validators still never rewrite a value.

## Decision, made on dev before any test number was seen
Option (a) of `docs/eval/failure_analysis.md` (written 2026-10-08 from `dev-final`, before the test split was ever
extracted). On dev it restores 11 withheld correct fields and 23 of 36 withheld rows. The test run `results/test-final`
(committed, grounding unfixed) is the baseline; its offline replay of this rule, run BEFORE writing this spec, predicts
17 restored scalar fields (256 -> 273 of 323 correct) and 21 of 34 withheld rows restored, with doc_002's four wrong values
(`9704.600` for a quote that prints `9.704.600`) staying withheld. That prediction is a hypothesis to check, not a target to
tune towards. The cap below is the existing `SHAPE_CAP` (0.7), a placeholder like the others; it is NOT tuned on test.

## Scope
- `validate/codes.py`: a new soft code `EVIDENCE_AMBIGUOUS = "evidence_ambiguous"` in `REASON_CODES`, not in `HARD_CODES`.
- `validate/grounding.py`: number grounding becomes three-valued: `grounded` (some span parses to exactly the value),
  `ambiguous` (no span grounds it, but some span is ambiguous and the value is one of its candidates), `ungrounded`
  (neither). Money scalars: grounded -> nothing; ambiguous -> `evidence_ambiguous`; ungrounded -> `evidence_not_grounded`
  (hard, as now). Row numeric cells (quantity, unit_price, amount): any ungrounded cell -> the row gets
  `evidence_not_grounded` and those cells are flagged (as now); otherwise any ambiguous cell -> the row gets
  `evidence_ambiguous` and those cells are flagged. "The value is one of the candidates" compares `Decimal` values exactly.
- `confidence/formula.py`: `CAP_BY_CODE[EVIDENCE_AMBIGUOUS] = SHAPE_CAP`.
- Replay of the committed test run through the real pipeline with the response cache (identical raw model answers, so the
  difference between the two runs is the validators and nothing else), compared with `scripts/compare.py`, promoted to
  `results/test-g1/`, with a short hand-written reading in `docs/eval/grounding_fix.md`.
- CLAUDE.md: the "Known flaw, reported not fixed" bullet and the grounding sentence say what is true now.

## Out of scope
- Dates (an ambiguous `05/03/2024` stays "not grounding": no date case was withheld on test), strings (the `Jl.`/`J1.` OCR
  slip), the abstention threshold, the other caps, the confidence formula's shape, the prompt, `normalize.py`.
- Any change to `ground_truth/`, `data/`, `results/test-final/`, scoring or comparison code.
- Re-extracting dev. The dev replay is `docs/eval/failure_analysis.md`'s counterfactual; the cache for dev holds a later
  `--cache refresh` sample, so a dev replay would not be paired with `dev-final`.

## Acceptance criteria
Offline and deterministic unless marked.
1. `python -m uv run pytest -q tests/test_validate_grounding.py tests/test_confidence.py tests/test_validate_document.py
   tests/test_extractor.py` -> all pass. New cases: an ambiguous span containing the value (either reading) -> soft code only,
   confidence capped at 0.7, status stays `extracted`; the same with a currency context -> no code at all; a value that
   matches neither reading -> `evidence_not_grounded`; a quote with one grounded and one ambiguous span for the same value
   -> no code; a row with an ambiguous cell -> row soft code and that cell flagged, row stays `extracted`; a row with one
   ambiguous and one ungrounded cell -> hard code; idempotence; `evidence_ambiguous` is in `REASON_CODES`, not in
   `HARD_CODES`, and has a cap.
2. `python -m uv run pytest -q tests/test_confidence.py -k "cap"` still proves `set(REASON_CODES) - {CONFIDENCE_BELOW_THRESHOLD}
   == set(CAP_BY_CODE)`.
3. Mutation pass on the new logic (`tests/mutants/grounding.py`): every mutant killed.
4. [Docker, replay, expected $0] `docker compose build`, `docker compose up -d --wait`,
   `docker compose run --rm eval --run-id test-g1` -> 25 documents, every call answered from the cache (`cached_calls` 25,
   cost paid $0). If any call is a live one (a cache miss), STOP and report: the run is then not a paired replay.
5. The raw model answers of `test-g1` are identical to `test-final`: for every document the `parsed` object and `raw_text`
   are byte-equal (a script in the acceptance run, not committed).
6. `python -m uv run python scripts/compare.py results/test-final outputs/runs/test-g1` -> exit 0 (no regression); the
   numbers (fields flipped each way, McNemar, accuracy before/after) are copied into `docs/eval/grounding_fix.md` whatever
   they are, with the prediction above next to them. A field that goes from correct to wrong is listed by name.
7. `promote_run.py outputs/runs/test-g1`, then `check_results.py` -> both results reproduce.
8. `python -m uv run pytest -q -m "slow or not slow"` and `python -m uv run ruff check` -> green (the known flaky
   `test_mutation_check` is rerun alone before it is called a failure).

## Risks
- A model that writes the wrong reading of an ambiguous quote (`84` for a printed `84.000` that is a weight) is "consistent" if
  its value equals a candidate -> only the two candidates pass, the confidence is capped, and the arithmetic checks still run;
  this is reported, not hidden, in `docs/eval/grounding_fix.md`.
- The replay may not be fully cached (JPEG pages re-encoded by another platform's libjpeg change the cache key) -> the Docker
  path is used because the first run was made there; criterion 4 stops on a live call instead of accepting a noisy sample.
- Restoring rows puts more rows into the document arithmetic (`lines_ne_subtotal`, `components_ne_total`): those are soft caps
  and may lower confidences or flag cells that were previously not checked -> expected and reported.
- Tuning to the test split: the rule was fixed on dev and predicted for test before the replay; if the replay disagrees with
  the prediction the rule is NOT adjusted to fit it.
