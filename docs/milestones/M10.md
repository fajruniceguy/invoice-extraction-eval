# M10: README, the agentic-development note, `.env.example`, and a repository hygiene pass

Status: spec (written before the README; not edited after approval)
Roadmap ref: docs/ROADMAP.md#M10; scope requested by the owner on 2026-10-09 ("README.md for final push, `.env.example`, check repo hygiene")

## Goal
A reviewer who opens the repository finds, in this order: what the system is, the result, how to run it in two commands, and the
reasoning behind it; every number in the README comes from a committed artifact and every claim that is not measured says so.

## Scope
- `README.md` with every section the brief lists: run commands, dataset / schema / approach and why, architecture, key trade-offs,
  eval results, the agentic-development note (and the extension actually used), what I would do with more time. Written for the
  reviewer, not for the owner: it states the weak results and the open question about three test labels as plainly as the
  strong ones.
- `.env.example`: still placeholders only, with the Docker-specific notes (the file is the compose `env_file`; the cost cap lives as
  long as the server process; a host-side model needs `host.docker.internal`) and the current measured numbers in the comments.
- A hygiene pass that CHANGES only what is safe and unambiguous, and REPORTS the rest: tracked files that should not be tracked,
  local paths or identities in tracked text, secrets (history and `.env` values), line endings, a clean-clone run of the whole
  suite, Docker build files, stale claims in the docs.
- `.gitattributes` (found by the pass: a default Windows checkout does not reproduce the committed scorecards because they hash
  label and manifest bytes).

## Out of scope
- Any change to `src/`, `scripts/`, `tests/`, `data/`, `ground_truth/`, `results/` (read-only here), the prompt, or a label.
- Adding sources to the manifest rows of downloaded documents (I do not know them: reported to the owner).
- Fixing `tools/mutation_check.py` (reported), running CI on GitHub (not possible from here), pushing.

## Files
- Create: `README.md`, `.gitattributes`, `docs/milestones/M10.md`
- Change: `.env.example`, `docs/DEVLOG.md`, `CLAUDE.md` (only where the README makes a line stale)
- Must NOT touch: `src/**`, `scripts/**`, `tests/**`, `data/**`, `ground_truth/**`, `results/**`, `.env`

## Acceptance criteria
Offline and deterministic.
1. Every number in the README appears in a committed file named next to it; a script-free check: for each figure, `grep` finds it in
   the cited artifact (done by hand and listed in the DEVLOG entry).
2. Every relative link and every command in the README resolves: each linked path exists; each documented command is run (offline
   ones) or dry-run (costly ones) in a clean clone.
3. `python -m uv run pytest -q tests/test_ci_and_env_example.py` -> pass (the example names every setting, loads as is, passes the secret
   scan).
4. A clean clone with a Windows-style checkout (`core.autocrlf=true`): `scripts/check_results.py` reproduces both committed results
   (it did not before `.gitattributes`).
5. A clean clone: `ruff check`, `pytest -q -m "slow or not slow"`, `make_probes.py --check`, `check_results.py` all green (the known
   flaky `test_mutation_check` is rerun alone).
6. `tools/secret_scan.py --worktree`, `--history`, `--env-values` -> 0 findings.
7. `git ls-files` holds no `.env`, cache, venv, `outputs/` content, raw document or unredacted preview.

## Risks
- A README that sounds better than the results -> every claim is tied to a file, weak results are in the first screen, and the open
  label question is stated where the results are.
- Numbers drift when a new run is made -> the README names the run (`test-g1`) and says a new run needs its numbers updated.
- The downloaded documents have no `source_url` -> the README says what the manifest records and does not invent provenance.

## Deviations from roadmap
- The roadmap lists the agentic note as a separate deliverable; it is a README section here, because the brief asks for it in the README.
