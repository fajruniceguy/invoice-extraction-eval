# M5: Eval harness — comparators, line-item matching, error taxonomy, scorecard

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#M5

## Goal
A run under `outputs/runs/<run_id>/` can be scored offline against ground truth: type-aware
field comparators, line items paired with a Hungarian assignment, every miss classified in a
documented error taxonomy, and a scorecard in markdown + JSON with per-doc results and a run
manifest recording git SHA, prompt hash, model, config, GT hash and dataset hash.

## Scope
- `evalkit/comparators.py`: value comparison by field kind. Constants `FUZZY_NAME_MIN = 0.90`,
  `NUMERIC_REL_TOL = Decimal("0.005")`, `NUMERIC_ABS_TOL = Decimal("0.01")` (documented as
  chosen defaults, not calibrated). `normalize_text(text)` = casefold, punctuation -> space,
  whitespace collapsed (same token rule as `validate/grounding.py`'s `_compact`, reimplemented
  here: evalkit must not depend on validate internals). Kinds + registry `FIELD_KIND`:
  - `name` (fuzzy): `vendor_name`, `buyer_name`, row `description`. Match if normalized-equal or
    `difflib.SequenceMatcher` ratio on the normalized strings >= `FUZZY_NAME_MIN`; the ratio is
    returned in the result (the taxonomy uses it for near-misses).
  - `text` (normalized exact): `vendor_address`, `payment_method` — equal after `normalize_text`.
  - `code`: `vendor_tax_id`, `document_number` — normalized exact, but when a value is
    mostly digits both sides compare on digits only ("01.234.567.8-901.000" == "012345678901000"),
    same rule as grounding. `currency`: normalized exact on the uppercased ISO code.
  - `number` (`subtotal`, `tax`, `discount`, `total`, row `quantity`, `unit_price`, `amount`):
    GT decimal strings parse with `Decimal` strictly (a label is already normalized; a bad label
    is a loud error, never re-guessed). Equal iff `abs(a-b) <= max(NUMERIC_ABS_TOL,
    NUMERIC_REL_TOL * abs(expected))`.
  - `date` (`document_date`, `due_date`): both sides resolved to `date` (typed values compare
    directly; strings go through `docextract.normalize.parse_date(day_first=True)`) and compared
    exactly. An ambiguous/invalid string is a mismatch, never a guess.
  - Every comparator returns `Comparison(matched, how, similarity)` with `how` in
    `exact | normalized | fuzzy | numeric | date`.
- `evalkit/matching.py`: `match_rows(predicted: list[LineItem], expected: list[GTLineItem]) ->
  RowMatch`. Cost of a pair = number of mismatched cells over (`description` fuzzy, `quantity`,
  `unit_price`, `amount` numeric); a GT cell that is `"__unlabeled__"` is excluded from the cost;
  a labeled `null` cell matches only a null cell. A hand-written O(n^3) Hungarian assignment
  (no scipy) minimizes total cost over the (padded, square) matrix, where leaving a row unpaired
  costs the number of compared cells (= a fully wrong pair). Costs are integers and the objective
  carries a lexicographic tie-break (`total = cost * (N*N + 1) + (i*N + j)`), so equal-cost
  assignments always resolve the same way. After the assignment, a pair where NO compared cell
  agrees is unwound into one missed + one spurious row. `RowMatch` = `pairs` (indices + per-cell
  `Comparison`), `missed` (GT indices), `spurious` (predicted indices).
- `evalkit/metrics.py`: scoring per labeled field and for rows.
  - Scalar outcome for one (GT, prediction) pair: `correct` (value matched; or GT `null` and
    prediction `absent`), `value_wrong` (both have values, mismatch), `should_be_absent`
    (GT `null`, prediction extracted — hallucination), `should_be_value` (GT value, prediction
    `absent`), `abstained` (prediction `abstained`), `no_prediction` (doc failed/refused/not_run,
    or the field is missing). GT `"__unlabeled__"` is skipped entirely.
  - Metrics ("both numbers"): `accuracy = correct / labeled` (abstentions and
    failures count as errors — the headline), `selective_accuracy = correct / answered`,
    `coverage = answered / labeled`, `abstention_rate = abstained / labeled`,
    `failure_rate = no_prediction / labeled`, where `answered = labeled - abstained - no_prediction`.
  - Rows: `row_precision = matched / (matched + spurious)`, `row_recall = matched /
    (matched + missed)`, `row_f1`, `row_accuracy = zero-cost pairs / matched`,
    `cell_accuracy = matching cells / compared cells` over matched pairs. GT `line_items: null`
    ("labeled: no itemization") scores `correct` iff the prediction has zero rows; predicted rows
    against it are `should_be_absent` + spurious. GT `"__unlabeled__"` skips rows.
- `evalkit/taxonomy.py`: the error vocabulary every non-correct outcome is classified into:
  `numeric_mismatch`, `date_mismatch`, `string_mismatch`, `name_near_miss` (a fuzzy-field
  mismatch with `similarity >= 0.5`), `hallucinated_value`, `missing_value`, `abstained_on_value`,
  `abstained_on_absent`, `no_prediction`, `row_missed`, `row_spurious`, `cell_mismatch`.
  `ERROR_CLASSES` (exhaustive tuple), `classify(...)` and per-doc/per-run counts. M6's flip
  analysis will reuse these names.
- `evalkit/scorecard.py`: `score_run(run_dir, *, manifest_rows, labels, now=None, git_sha=None)
  -> Scorecard` + `to_json` / `to_markdown` writers.
  - Scores each ok record's `validated` (the pipeline's output; `parsed` is not scored). Docs
    whose label is missing are listed as `unscored`, never an error. Borrowed labels resolve via
    `evalkit.gt_store.load_labels` (label once, never copy).
  - Outputs under `<run_dir>/score/`: `manifest.json`, `scorecard.json`, `scorecard.md`,
    `docs/<doc_id>.json` (per-field expected/predicted/status/outcome/error_class/how/similarity,
    the row assignment with per-cell outcomes, doc metrics and error counts).
  - Run manifest (`manifest.json`) records: `run_id`, `scored_at`, `target: "validated"`,
    from `run.json`: `prompt_sha256`, `schema_sha256`, `model`, `settings` (config), `selection`;
    computed at score time: `git_sha` (via `git rev-parse HEAD`, `"unknown"` when unavailable;
    injectable for tests) + `git_dirty`, `gt_hash`, `dataset_hash`, and the comparator settings
    used (score-time manifest; `run.json` and M3 code are untouched).
  - `gt_hash` = sha256 over sorted lines `<owner_doc_id>\t<sha256 of that label file's bytes>`,
    one line per OWNER file actually used (borrowers add no line).
  - `dataset_hash` = sha256 over `sha256(manifest.csv bytes)` plus, per scored doc, a line
    `<doc_id>\t<p1 sha256>\t<p2 sha256>...` from the page hashes its sidecar records
    (`ingest.json`, or `degrade.json` for a variant — metadata only, pages are never read).
    A doc with no sidecar contributes `<doc_id>\t(none)`.
  - Slices: tables per `split`, `doc_type`, `capture` (manifest columns) with labeled counts and
    the two accuracies + coverage. `now` is injectable so output is byte-deterministic.
- `scripts/score.py`: `python -m uv run python scripts/score.py outputs/runs/<run_id>
  [--manifest data/manifest.csv] [--pages-dir data/pages] [--gt-dir ground_truth]
  [--out <run_dir>/score]`. Strictly parses `run.json` + `docs/*.json` into `DocRecord`s (same
  style as `scripts/check_run.py`). Exit 0 = at least one document scored (summary printed);
  exit 1 = structural problem (no run.json, unreadable record/label, a scored doc not in the
  manifest).

## Acceptance criteria
Offline and deterministic. None cost money.
1. `python -m uv run pytest -q tests/test_comparators.py` -> all pass. Covers: "PT. Acme" matches
   "pt acme" (normalized), tax ids matching on digits only, currency case, a fuzzy pair at 0.90
   accepted and one at ~0.89 rejected (constructed strings), `1250000` == `1250000.00`,
   `123874` vs `123873.99` within tolerance, `1000` vs `1006` outside, "5 Maret 2024" ==
   `2024-03-05`, an ambiguous date string -> mismatch (no guessing).
2. `python -m uv run pytest -q tests/test_matching.py` -> all pass. Covers: shuffled rows pair
   optimally; equal-cost assignments are deterministic (identical across runs); 2 predicted vs
   3 GT rows -> 1 `missed`; fully disjoint rows -> `missed` + `spurious`; an `"__unlabeled__"`
   GT cell is excluded from the cost; a 40x40 case completes and pairs the identity.
3. `python -m uv run pytest -q tests/test_metrics.py` -> all pass. Covers: the full GT-state x
   prediction-state matrix (value/null/unlabeled vs extracted/absent/abstained/missing);
   `abstained` and `no_prediction` are errors in `accuracy` and excluded from
   `selective_accuracy`; `coverage` counts; GT `line_items: null` vs predicted rows; row
   precision/recall/F1 and cell accuracy on a matched set.
4. `python -m uv run pytest -q tests/test_taxonomy.py` -> all pass. Covers: every non-correct
   outcome gets exactly one class from `ERROR_CLASSES`; a 0.5-0.9 name similarity lands in
   `name_near_miss`, a low one in `string_mismatch`; counts sum to the wrong totals.
5. `python -m uv run pytest -q tests/test_scorecard.py` -> all pass. Covers: a synthetic run dir +
   labels -> `scorecard.json`/`scorecard.md` + per-doc results with the documented sections;
   `manifest.json` contains git SHA, prompt hash, model, config, `gt_hash`, `dataset_hash`;
   scoring twice with the same injected `now`/`git_sha` -> byte-identical output; editing one
   label file changes `gt_hash` and editing the manifest changes `dataset_hash`; unscored docs
   are listed, not errors.
6. `python -m uv run pytest -q -m slow tests/test_score_script.py` -> passes: `scripts/score.py`
   as a subprocess over a fixture run dir -> exit 0, `score/manifest.json`, `scorecard.json`,
   `scorecard.md`, `score/docs/*.json` written; a run dir without `run.json` -> exit 1.
7. `python -m uv run pytest -q -m "slow or not slow"` -> all pass;
   `python -m uv run ruff check` -> `All checks passed!`
8. `python -m uv run python scripts/score.py outputs/runs/m4-live` -> exit 0 and a scorecard over
   cons_001..003 (offline: this is the M4 run already on disk; labels are
   `ground_truth/cons_00{1,2,3}.json`). Report states accuracy, selective accuracy, coverage and
   row metrics. If `outputs/runs/m4-live` is absent: regenerate it by M4's criterion 10 command
   with the warm response cache ($0) — not run without approval.

## Risks
- Pairing semantics change row precision/recall (forced min(n,m) pairing vs. the unwound
  disjoint pairs) -> the rule is fixed here, identical for every scored run, so M6 compares like
  with like; `row_accuracy` and `cell_accuracy` carry the content signal either way.
- difflib ratio is weaker than token-set similarity on company-name noise (PT/CV prefixes,
  reordered words) -> `name_near_miss` makes those visible in the taxonomy; rapidfuzz is the
  documented upgrade path (zero new deps chosen).
- `gt_hash`/`dataset_hash` must change exactly when their input changes -> one small reader per
  hash, mutation-tested; label bytes hashed as stored (no re-serialization).
- Labeled set is 3 constructed invoices today -> criterion 8 is structurally meaningful but
  statistically thin until M2's human labeling lands; the synthetic fixtures carry the tests.
- Strict record parsing may refuse hand-edited run dirs -> same strictness as `check_run.py`, and
  that is deliberate (a silently skipped document would skew a scorecard).

## Deviations from roadmap
- "Run manifest" is written by the scorer at score time (`score/manifest.json`) and copies prompt
  hash/model/config from `run.json`; git SHA, GT hash and dataset hash are computed when scoring.
  `run.json`/M3 code untouched (decided with you).
- "Fuzzy names with threshold" applies to `vendor_name`, `buyer_name` and row `description`;
  other strings are normalized-exact and numeric fields use the tolerance (decided with you).
- How `abstained` scores (left open in M4's spec) is decided here: wrong in the headline accuracy,
  excluded from selective accuracy, always visible in coverage (decided with you).
