# G3: ground a quantity printed with a multiplication sign (`x1`, `2x`)

Status: spec (written before code; not edited after approval)
Roadmap ref: none (post-submission fix; the flaw is recorded in README "Known limitations")

## Goal
A line-item quantity that the document prints with a multiplication sign glued to the number (`x1`, `2x`, `×3`) is found in its own
evidence quote, so a correct row is no longer withheld as `evidence_not_grounded`. Measured by re-running the 16-document test split
from the response cache: the nine rows of doc_027 (7) and doc_020 (2) are restored and nothing else moves.

## Scope
- `validate/grounding.py`: for the `quantity` cell only, a whitespace token that is a number with a leading or trailing `x` / `X` / `×`
  (`x1`, `2x`, `X3`, `×3`, also inside the punctuation the existing candidate step strips: `(2x)`, `x1,`) also offers the bare number to the
  parser. The parser, its ambiguity rules and the `evidence_ambiguous` code are unchanged: `x1.250` with no currency is as ambiguous as `1.250`.
- Tests first (they fail on the current code), a real-data test on the committed doc_027 answer, mutants for the new rule.
- A new committed result `results/test-g3` (the same raw answers, replayed from the local cache; validators are not in the cache key) and a short
  report `docs/eval/quantity_marks.md` with the before/after against `results/test-public` and the cases this does NOT fix.
- README / results index / CLAUDE.md / DEVLOG lines that called the flaw open.

## Out of scope
- Money cells and scalar fields: the marker is read for a quantity only. `x4.50` still does not ground a unit price (a looser rule widens what a
  wrong value can hide behind).
- Quantities glued to a unit (`2pcs`, `250ml`): deliberately not read; `250ml` would ground a quantity of 250.
- doc_021 (2 rows) and doc_033 (1 row), the other three `evidence_not_grounded` rows of `test-public`: different problems (the model's quote does
  not contain the amount; a minus sign split from its digits by `IDR`). Reported in the report, not fixed here.
- `normalize.py`, the prompt, confidence caps, labels, the manifest, any request that is not a cache hit.

## Prediction (written before any run)
On `test-g3` against `test-public`: scalar fields 186/207, unchanged. Line items matched 135 -> 144, missed 10 -> 1, spurious 48 -> 39; row F1 0.823 -> 0.878
overall and 0.532 -> 0.677 on the 14 real documents (constructed unchanged at 1.000). It is an upper bound for the rows: a restored row can still miss on its
description. `compare.py` verdict: no regression (exit 0).

## Acceptance criteria
Offline and deterministic except step 4.
1. `python -m uv run pytest -q tests/test_validate_grounding.py` -> all pass; with the source change reverted, the new tests fail.
2. `python -m uv run python tools/mutation_check.py tests/mutants/grounding.py` -> exit 0, every mutant killed (new ones included).
3. `python -m uv run pytest -q -m "slow or not slow"` and `python -m uv run ruff check` -> green.
4. [COSTS MONEY: expected $0; all 16 answers are in the local cache; the API runs with `MAX_RUN_COST_USD=0.0001` and concurrency 1, so a miss costs one
   call of about $0.01 at most] `scripts/eval_api.py --split test --run-id test-g3` against a local API -> 16 ok, 16 `[cached]`.
5. `python -m uv run python scripts/compare.py results/test-public outputs/runs/test-g3` -> exit 0.
6. No row of `test-g3` that `test-public` returned as grounded changes status (no row is newly abstained), and the nine rows carry no `evidence_not_grounded`.
7. `python -m uv run python scripts/promote_run.py outputs/runs/test-g3` then `scripts/check_results.py` -> `test-public` and `test-g3` both reproduce.
8. `python tools/secret_scan.py --worktree` -> 0 findings.

## Risks
- A product code that looks like a marker (`X5` in a model name) grounds a quantity of 5 that the model got wrong -> accepted: quantity cell only, exact
  token shape, and grounding is self-consistency, not truth (README, "Grounding is self-consistency").
- The fix helps the two documents that print `x1` / `2x` and nothing else, so the headline gain is bounded by them -> the report says so and gives the
  per-document numbers; with 14 real documents no gain here is evidence for another dataset.
- The replay misses the cache for some document -> the cost cap bounds it; a miss is a new sample, and is reported as one.
