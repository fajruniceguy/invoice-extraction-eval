# S1: Failure analysis, run-to-run noise and calibration (dev split)

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#S1 (calibration), extended with the failure analysis and the noise floor that feed it

## Goal
Three offline reports over existing dev runs say, with numbers: how the system fails by kind (including what the model
said before a field was withheld), how much two identical runs differ from each other, and whether the confidence
means anything (reliability, risk-coverage, and the abstention threshold the rule would choose on dev).

## Scope
- Context (measured on `dev-final`, DeepSeek V4 Flash Vision, effort medium): 99 of 122 labeled fields correct, 13
  abstained, 7 wrong, 2 missed. Exploration found that 11 of the 13 abstentions withheld a value that was CORRECT before
  the validators ran, and that 12 of 13 carry the HARD code `evidence_not_grounded` (not the confidence threshold):
  receipts that print `208,179` or `84.000` with no currency marker are ambiguous to the normalizer, and an ambiguous
  span is not grounding. This tooling must quantify that, not hide it.
- `evalkit/failures.py` (pure, offline): `FieldCase` for every labeled scalar field of every ok document (expected, the
  `parsed` and the `validated` outcome scored with the scorer's own `score_field`, both confidences, the reason codes,
  the document); `collect_cases(run_dir, ...)`; tables: validated x parsed outcome, abstentions by reason code with the
  share whose raw value was right, the same by field, and row misses/spurious rows per document; markdown renderer.
- `evalkit/noise.py` (pure, offline): given N runs of the same setting, the pairwise flips (reusing `compare_runs`), the
  accuracy range and spread, and the spread of output tokens, cost and latency overall and per document.
- `evalkit/calibration.py` (pure, offline): pools the cases of one or more runs. The correctness target is the
  correctness of the value the system would return at a threshold t: the validated value if it is extracted, the
  `parsed` value if a threshold-only abstention is lifted; a HARD-code abstention stays abstained whatever t is.
  Reports: reliability table (fixed bin edges 0.5, 0.7, 0.8, 0.9, 0.95, 1.0 -> bins, mean confidence, accuracy, count),
  ECE and Brier, risk-coverage points over the distinct confidence values, area under the risk-coverage curve, and the
  threshold chosen by the rule below. SVG diagrams are written by hand (no plotting dependency).
- **The rule for the threshold, fixed before any result:** the lowest t (highest coverage) whose pooled selective
  accuracy on dev is at least 0.95; if no t reaches it, say so and keep the current `ABSTAIN_BELOW`. The report states
  the threshold in force, the chosen one, and the headline accuracy, selective accuracy and coverage at each.
- Honesty: pooled runs of the same 10 documents are not independent samples; every report says "10 independent
  documents" and the threshold is a recommendation for dev, to be reported on test once test labels exist (not here).
- Scripts: `scripts/analyze_failures.py RUN... [--out FILE]`, `scripts/noise_report.py RUN... [--out FILE]`,
  `scripts/calibrate.py RUN... [--out FILE] [--svg-dir DIR]`. Same inputs give byte-identical output.
- Reports committed: `docs/eval/failure_analysis.md`, `docs/eval/noise.md`, `docs/eval/calibration.md` and two SVGs.
- Live part [COSTS MONEY, about $0.20, about 15 minutes, already approved in conversation]: three `--cache refresh`
  re-runs of `dev-final` (`dev-final-r1..r3`) are the noise sample. Everything else is offline.

## Out of scope
- Changing `validate/`, `confidence/` (including `ABSTAIN_BELOW` and the caps), `normalize.py`, the prompt or the
  extractor. The grounding finding is reported with options; fixing it is a separate decision and milestone.
- The test split and blind documents (nothing here reads them), S2/S3/S5/S7, S4 (own spec), a plotting library.

## Acceptance criteria
Offline and deterministic unless marked.
1. `python -m uv run pytest -q tests/test_failures.py tests/test_noise.py tests/test_calibration.py` -> all pass: the
   outcome cross-table and the "raw value right" share on hand-built cases; a threshold-only abstention is lifted at a
   lower t but a HARD one never is; reliability bins and ECE/Brier against hand-computed values; the risk-coverage
   curve is monotone in coverage; the threshold rule on literal tables (reached / not reached / tie); pairwise flips
   count regressions plus improvements; same inputs -> identical bytes.
2. `python -m uv run pytest -q -m slow tests/test_eval_scripts.py` -> the three scripts on a run built with the fake
   server: exit 0, files written, bad input exits 2.
3. `python -m uv run python scripts/analyze_failures.py outputs/runs/dev-final` -> exit 0; the report says 13
   abstentions and how many carried a correct raw value (11 expected).
4. `python -m uv run python scripts/noise_report.py outputs/runs/dev-final outputs/runs/dev-final-r1 outputs/runs/dev-final-r2 outputs/runs/dev-final-r3` -> exit 0.
5. `python -m uv run python scripts/calibrate.py` on the same four runs -> exit 0, two SVGs, the chosen threshold or
   "not attainable" stated with its rule.
6. [COSTS MONEY ~$0.20] the three re-runs finished with 10 ok documents each (done before criteria 4 and 5).
7. `python -m uv run pytest -q -m "slow or not slow"` and `python -m uv run ruff check` -> green.

## Risks
- Four runs of the same 10 documents look like 40 documents but are 10 -> every report states it and no interval is
  shrunk by pooling.
- The pooled correctness target mixes validated and parsed values -> defined above, tested, and the unlifted (HARD)
  fields are shown separately.
- A threshold fitted on dev overfits -> it is only a recommendation; test reporting waits for test labels.
- Changing the validators is the obvious fix for the grounding finding and tempting -> explicitly out of scope; the
  report lists the options and the owner decides.

## Deviations from roadmap
- S1 in the roadmap is calibration only; the failure analysis and the noise floor are added because the threshold cannot
  be interpreted without them. "Reported on test" is deferred until the test split is labeled.
