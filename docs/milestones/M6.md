# M6: Regression comparison — diff two runs, test the difference, gate on it

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#M6

## Goal
`scripts/compare.py BASELINE_RUN CANDIDATE_RUN` diffs two extraction runs offline: what changed between
them, every field that flipped, an exact paired test plus a paired bootstrap interval, a verdict and an
exit code that is non-zero when the candidate is significantly and materially worse. It is demonstrated
catching a deliberately degraded prompt, and the demonstration is documented.

## Scope
- `evalkit/compare.py` (fills the one-line stub; imports the M5 modules, edits none of them):
  - `mcnemar_exact(regressions, improvements)`: exact binomial on the discordant pairs, integers and
    `Fraction` (no scipy). `p_worse` = P(X >= b), `p_better` = P(X >= c), `p_two_sided` =
    min(1, 2 P(X <= min(b, c))), X ~ Binomial(b + c, 1/2); with no discordant pair all three are 1.
  - `paired_bootstrap(clusters, seed, resamples, level)`: a cluster is (pairs, baseline_correct,
    candidate_correct) of one label owner (`DocumentScore.owner`, so a variant or duplicate resamples with
    the document it borrows its label from); seeded `random.Random`; percentile interval of
    delta = candidate accuracy - baseline accuracy; level fixed at 0.95.
  - `compare_runs(...)`: `score_run` for both runs (labels as they are now; a stored `score/` is never
    read) -> pair on (doc_id, field name) over the documents scored in BOTH runs -> a flip per pair:
    `regression` (correct -> not correct), `improvement`, `changed_wrong` (wrong both times, different
    outcome or error class) or `unchanged`. Reported: the 2x2 table, a per-field table, the headline
    metrics, the row metrics and the error-class mix (`ERROR_CLASSES`) of each run with their deltas,
    all restricted to the paired documents; per-slice accuracy deltas (`SLICE_COLUMNS`); "what differs"
    (model, endpoint, prompt hash, schema hash, every settings key); comparability notes: documents scored
    in one run only, documents whose run status differs, documents whose stored-page hashes differ between
    the runs (read from the two runs' document records), and fewer than 10 independent documents (fields
    inside a document are not independent, so the McNemar p is optimistic).
  - `Thresholds(alpha=0.05, max_drop=0.02)` and `decide(...)`: verdict `regression` iff
    `p_worse <= alpha` AND `baseline accuracy - candidate accuracy >= max_drop`, otherwise `ok`. Both
    comparisons are exact (`Fraction`), so the boundary is the stated `<=` / `>=` and never float noise.
    The bootstrap interval is reported next to the verdict and is not part of it.
  - `Comparison.to_json()` (sorted keys) and `to_markdown()`: no timestamps, byte-stable for the same
    inputs. Line items are compared in aggregate (row precision/recall/F1, row and cell accuracy, error
    mix), not flip by flip.
- `scripts/compare.py`: `compare.py BASELINE CANDIDATE [--alpha 0.05] [--max-drop 0.02]
  [--resamples 10000] [--seed 1] [--max-flips 30] [--manifest FILE] [--pages-dir DIR] [--gt-dir DIR]
  [--out DIR]`. Default out `outputs/compare/<baseline>__vs__<candidate>/` holding `comparison.json` and
  `comparison.md`. The verdict is the first line of stdout. Exit codes: 0 no regression, 1 regression,
  2 cannot compare (bad arguments, a run folder that is missing or unreadable, a label that cannot be
  read, no labeled document scored in both runs). This differs from `score.py`, where 1 means "could not
  be scored": a gate needs 1 to mean "regressed".
- `--system-prompt-file PATH` on `scripts/extract.py`: a `system_prompt` parameter (default: the production
  prompt) on `build_messages`, `extract_pages` and `run_extraction`, and `prompt_sha256(system_prompt)` in
  `extract/prompt.py` (`PROMPT_SHA256` keeps its value). The run record carries the hash of the prompt it
  used. The file is read as UTF-8 text with universal newlines (a CRLF checkout hashes the same); a missing
  or blank file is exit 2 before any request.
- Demo assets: `docs/demo/degraded_prompt.txt`, a frozen artifact (the production prompt with three
  documented edits) and `docs/demo/regression_demo.md` (the edits, the commands, the verbatim compare
  output, the caveats). The edits: E1 swaps the `subtotal` and `total` definitions; E2 asks for every money
  amount "in thousands of rupiah" (a silent unit error that passes every internal validator and is only
  caught against the labels); E3 replaces the absent / never-guess rule with "always give your best
  estimate".

## Out of scope
- Per-row (line-item) flips and a test on rows: M5 keeps no per-ground-truth-row verdict.
- Cost and latency deltas (M7); sweeps and before/after tables (M8); comparing more than two runs.
- Measuring run-to-run noise with `--cache refresh` (costs money); CI wiring (S6).
- Any labeling or data work (the M2 human steps stay with the user: classify, redact, split, label) and
  repeating the demonstration on real dev documents (a follow-up once they are labeled).

## Acceptance criteria
Offline and deterministic unless marked.
1. `python -m uv run pytest -q tests/test_extractor.py tests/test_extract_runner.py tests/test_extract_script.py`
   -> all pass. Covers: the default prompt is unchanged (`build_messages` with and without the argument are
   equal; `PROMPT_SHA256` equals the legacy formula and `prompt_sha256(SYSTEM_PROMPT)`); an override reaches the
   request body and `run.json`; a missing or blank file is exit 2 with no request reaching the fake server.
2. `python -m uv run pytest -q tests/test_compare.py` -> all pass. Covers: McNemar literals (5 regressions /
   0 improvements -> p_worse 1/32; 4/0 -> 1/16; 7/1 -> 9/256; 6/1 -> 1/16; 3/3 -> 0.65625 with two-sided 1.0;
   no discordant pair -> 1.0; two-sided for 6/0 -> 1/32); the flip matrix including `abstained` and
   `no_prediction`; pairing on the intersection with one-run-only documents listed; metrics restricted to the
   paired documents; per-field and error-mix deltas; a seeded bootstrap (same seed, same interval; owners
   resampled together; clusters with identical deltas give a zero-width interval); gate boundaries (p equal to
   alpha fires, just above does not; a drop equal to max-drop fires, just below does not) and the AND
   (significant but small drop -> ok; large drop but not significant -> ok); identical runs -> 0 flips, p 1.0,
   ok; an improvement -> ok; byte-identical JSON and markdown on a second call; a page-hash mismatch and a
   prompt-hash difference are reported.
3. `python -m uv run pytest -q -m slow tests/test_compare_script.py` -> passes: the real CLI in a subprocess
   exits 0 (identical runs), 1 (a degraded run), 2 (a missing run folder, no labeled document in common, a bad
   `--alpha`); the artifacts are written; the verdict is the first line of stdout.
4. `python -m uv run pytest -q tests/test_degraded_prompt.py` -> passes: the file's text hash is pinned (it is a
   frozen artifact, so a later production-prompt edit does not break it); it lacks the three phrases the edits
   remove and holds the three they add.
5. `python -m uv run pytest -q -m "slow or not slow"` -> all pass; `python -m uv run ruff check` -> `All checks passed!`
6. `python -m uv run python scripts/compare.py outputs/runs/m4-live outputs/runs/m4-live --out outputs/compare/aa1`
   -> exit 0, verdict ok, 39 fields paired, 0 flips, p_worse 1.000; the same with `--out outputs/compare/aa2`
   gives a byte-identical `comparison.json` (`(Get-FileHash <file>).Hash` equal). If `outputs/runs/m4-live` is
   absent: regenerate it with M4's criterion-10 command from the warm response cache ($0), not run without approval.
7. [COSTS MONEY ~ $0.11-0.15 at list price (the three baseline calls cost $0.114), 3 of the day's free-tier
   requests; run only after approval]
   `$env:LLM_MAX_RETRIES = 1; python -m uv run python scripts/extract.py --doc cons_001 --doc cons_002 --doc cons_003 --system-prompt-file docs/demo/degraded_prompt.txt --run-id m6-degraded`
   then `python -m uv run python scripts/compare.py outputs/runs/m4-live outputs/runs/m6-degraded` -> exit 1; "what
   differs" lists the prompt hash only; at least 5 regressions with p_worse <= 0.05 and a drop >= 2 points; the
   flips fall on the fields the edits target; running compare again is byte-identical. The output is pasted into
   `docs/demo/regression_demo.md`. The recipe (the three edits) may be tuned if it does not trigger; the
   criterion may not be loosened; at most 2 attempts (~$0.30) before coming back to the user.

## Risks
- 39 paired fields from 3 easy documents: the gate only fires at >= 5 net regressions (13% of the fields), and the
  McNemar p is optimistic because fields inside a document are not independent -> every report carries the
  few-independent-documents caution and the document-level bootstrap interval; the demonstration document says so;
  repeating it on `--split dev` is listed as the next step.
- The degraded prompt may not move 5 fields -> E2 alone should flip about 11 money fields, E1 and E3 are backups;
  only the recipe is tuned, never the criterion.
- Free-tier quota (20 requests/day/model per the 2026-10-07 notes) and 503 retries that count against it ->
  `LLM_MAX_RETRIES=1`, 3 documents per attempt; on a 429 stop and ask.
- `m4-live` must be comparable: if the `.env` settings changed since (model, reasoning effort, image size) "what
  differs" shows more than the prompt and the demonstration is confounded -> re-run the baseline live (~$0.11) only
  with approval.
- `--system-prompt-file` sits on the production path -> the default behavior is pinned by tests (messages, hash)
  so the warm cache and every earlier run record stay valid.
- Hand-written statistics fail quietly (tail direction, off-by-one at the boundary) -> expectations are literal
  numbers computed independently of the code, plus a mutation pass (tail direction, `<=` / `<`, `>=` / `>`, pairing
  key, cluster key, paired-only restriction, ignored seed).
- The exit-code convention differs from `score.py` -> stated in the script docstring, this spec and the tests.

## Deviations from roadmap
- "McNemar or a paired bootstrap": both are computed; McNemar gates, the bootstrap is reported.
- "Per-field flips": scalar fields are compared flip by flip; line items in aggregate.
- "Exits non-zero past a threshold": exit 1 iff the exact one-sided McNemar p <= alpha AND the accuracy drop >=
  max-drop (decided with the user); 2 means "cannot compare".
- "Demonstrated on a deliberately degraded prompt": on the constructed trio until real dev labels exist (decided
  with the user, who also chose to label dev first and test later, so M6 proceeds without the M2 human steps the
  M5 DEVLOG entry listed before it).
