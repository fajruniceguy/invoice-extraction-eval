# M4: Validators, confidence and abstention

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#M4

## Goal
Every extracted value is checked against arithmetic reconciliation, field checks and its own evidence quote;
every field/row ends up carrying value, confidence, evidence, status and reason codes, where confidence is the
model's score lowered by documented, deterministic caps and a low confidence or a hard failure abstains the
field with a reason.

## Scope
- `validate/codes.py` (new): the reason-code vocabulary (`REASON_CODES`), a leaf module (no imports from
  `validate`/`confidence`) so `confidence/` can use it without a cycle. `QTY_X_PRICE_NE_AMOUNT` moves here and
  is re-exported from `validate/arithmetic.py` (its tests stay untouched).
- `validate/arithmetic.py` (extend): document reconciliation, reusing `tolerance()` and
  `MISMATCH_CONFIDENCE_CAP`, skipping any equation whose participants are not all `extracted`:
  - `lines_ne_subtotal`: sum of row amounts (rows with a non-null amount) vs `subtotal`;
  - `components_ne_total`: `subtotal + tax - discount` vs `total` (absent tax/discount count as 0; when
    `subtotal` is not extracted but rows are, the summed rows stand in for it).
  A mismatch adds its reason code to the summary fields and caps their confidence. Never a status change
  (printed documents can legitimately not add up — same rationale as the row check). Idempotent: strip own
  codes before re-adding.
- `validate/fields.py` (new):
  - dates: `due_date < document_date` -> `due_date_before_document_date` on `due_date` (HARD: abstains it);
    `document_date` after `today` -> `document_date_in_future` (soft; `today` injectable for tests).
  - currency: `currency` extracted but not a code `normalize.convention_for` can read -> `currency_unknown`
    (soft); a currency marker ("Rp", "$", ...) in a money field's evidence that contradicts `currency`
    -> `currency_contradicts_evidence` (soft). New public helper `normalize.currency_marker(text)`.
  - tax id: `vendor_tax_id` with 15/16 digits (old/new NPWP) is clean; other digit counts ->
    `tax_id_unusual_shape`; no digits at all -> `tax_id_implausible` (both soft).
- `validate/grounding.py` (new) — evidence self-consistency, per `extracted` field/row:
  - typed values (money, dates, quantities): some span of the quote parses with `normalize.parse_number` /
    `parse_date` (document currency / day-first context) to exactly the value -> grounded. "Rp 1.250.000,00"
    grounds `1250000.00`; "5 Maret 2024" grounds `2024-03-05`. An ambiguous parse is not grounding (never
    guess).
  - strings (names, addresses, payment method, document numbers, tax ids): normalized containment (casefold,
    punctuation- and whitespace-insensitive; mostly-digit values compare on digits only, so
    "01.234.567.8-901.000" is found in a quote that formats it differently).
  - a non-null value not traceable -> HARD `evidence_not_grounded`: field abstained (value null, evidence
    kept); for a row, the offending cells go in `flagged_cells` and the row is abstained (cells nulled).
  - `description` not found in the quote -> soft `description_not_verbatim` (row stays extracted, cell
    flagged): a reworded description must not kill an otherwise grounded row.
- `confidence/formula.py` (new): the confidence formula. `final = min(model_score, caps of its reason codes)`,
  never raised, idempotent (validating twice cannot lower twice): `ARITHMETIC_CAP = 0.5` (shared with
  `MISMATCH_CONFIDENCE_CAP`), `SHAPE_CAP = 0.7` (soft field/shape flags), `NORMALIZED_CAP = 0.85` (a value the
  normalizer had to rewrite; targets read from `LLMResponse.normalizations` labels via new
  `extract/preprocess.py::change_label`). Constants are documented placeholders for S1 calibration, like
  `MISMATCH_CONFIDENCE_CAP` already is.
- `confidence/abstain.py` (new): abstention policy -> `extracted` fields/rows become `abstained`
  (value/cells null, reasons kept and added) when: final confidence < `ABSTAIN_BELOW`, or a hard check failed
  (`evidence_not_grounded`, `due_date_before_document_date`). Code `confidence_below_threshold`. `absent`
  fields are never flipped. `ABSTAIN_BELOW = 0` disables the threshold.
- `validate/__init__.py` (change): `validate_document(document, *, abstain_below, normalizations=(),
  today=None)` runs the chain on the RAW parsed output and returns a copy: row arithmetic -> reconciliation ->
  field checks -> grounding -> `apply_confidence` -> `apply_abstention`. Exposes `REASON_CODES`.
- `extract/extractor.py` (change): `validate_line_items(parsed)` becomes `validate_document(parsed,
  abstain_below=settings.abstain_below, normalizations=response.normalizations)`. `Extraction.parsed` (what
  the model said) and `.validated` (what the validators concluded) keep their meaning. **No schema change**, so
  `schema_hash` and M3's response cache stay valid.
- `config.py` + `.env.example` (change): `abstain_below: float = Field(default=0.3, ge=0.0, le=1.0)`
  (`ABSTAIN_BELOW`; 0 = never abstain on confidence).
- `scripts/check_run.py` (new): makes the DoD runnable. Over `outputs/runs/<run_id>/` it checks every field
  and row of each ok record's `validated`: value/confidence/status present, confidence in [0,1], `extracted`
  => non-empty evidence + page in 1..pages sent, `absent`/`abstained` => null value, `abstained` => >= 1
  reason, every reason in `REASON_CODES`, `flagged_cells` within `CELL_NAMES`. Prints totals (fields, rows,
  abstained, flagged) and `all fields carry value/confidence/evidence/status/reasons`; exit 0 / 1 with the
  offenders named.

## Out of scope
- Grounding against actual page text (OCR / PDF text layer): no page text exists in the stack; a text sidecar
  would survive redaction as text (privacy conflict) and OCR is N1's territory. Self-consistency is the
  agreed M4 semantics.
- Calibration (reliability diagram, risk-coverage, choosing `ABSTAIN_BELOW` on dev): S1. The caps and the 0.3
  default are documented placeholders.
- Self-consistency sampling / a second sample: S2. Hallucination probe set: S4.
- Scoring, comparators, error taxonomy, scorecard, run manifest (M5). How `abstained` scores is M5's decision.
- Any change to `extract/schema.py` shape, the prompt, the provider client, ingest, evalkit, the labeling app.
- Fixing `smoke.py`'s stale default image folder (M3 debt).

## Acceptance criteria
Offline and deterministic (1-9). The one costly criterion is 10.
1. `python -m uv run pytest -q tests/test_validate_arithmetic.py` -> all pass, and
   `git diff --quiet HEAD -- tests/test_validate_arithmetic.py` -> exit 0 (row arithmetic unchanged).
2. `python -m uv run pytest -q tests/test_validate_totals.py` -> all pass. Covers: `lines_ne_subtotal` and
   `components_ne_total` within `tolerance()`; each equation skipped when a participant is absent/abstained or
   a row has no amount; a mismatch caps the summary fields at `MISMATCH_CONFIDENCE_CAP` and adds its reason,
   with no status change; twice-validated == once-validated.
3. `python -m uv run pytest -q tests/test_validate_fields.py` -> all pass. Covers: `due_date` before
   `document_date` -> `due_date` abstained with `due_date_before_document_date`; future `document_date`
   (injected today) -> capped + `document_date_in_future`; unknown currency -> `currency_unknown`; a "Rp" in a
   money field's evidence against `currency: USD` -> `currency_contradicts_evidence`; NPWP-shaped tax id clean,
   12 digits -> `tax_id_unusual_shape`, "NPWP-ABC" -> `tax_id_implausible`.
4. `python -m uv run pytest -q tests/test_validate_grounding.py` -> all pass. Covers: "Rp 1.250.000,00" grounds
   `1250000.00` and "5 Maret 2024" grounds `2024-03-05` through the shared normalizer; punctuation/case
   variants of names and tax ids ground; an ungrounded scalar -> abstained + `evidence_not_grounded`; an
   ungrounded numeric cell -> row abstained with that cell in `flagged_cells`; a missing description ->
   `description_not_verbatim`, row still extracted; an ambiguous quote span is not grounding.
5. `python -m uv run pytest -q tests/test_confidence.py` -> all pass. Covers: confidence = min(model score,
   caps of its reasons) and is never raised; a normalized value gets `NORMALIZED_CAP` (targets from
   `normalizations` labels); applying the formula twice changes nothing; `ABSTAIN_BELOW` abstains extracted
   fields and rows below it with `confidence_below_threshold` and never flips `absent`; every abstained field
   has >= 1 reason.
6. `python -m uv run pytest -q tests/test_validate_document.py tests/test_check_run.py` -> all pass. Covers:
   the full chain on one synthetic document (raw `parsed` unchanged, `validated` carries codes and capped
   confidence); `check_run` over a run dir written from the fake server -> exit 0 printing
   `all fields carry value/confidence/evidence/status/reasons`; the same run with one evidence stripped ->
   exit 1 naming the field.
7. `python -m uv run pytest -q tests/test_extractor.py tests/test_extract_runner.py` -> all pass: one request
   per document unchanged, `validated` is the post-M4 result, `parsed` still the model's words.
8. `python -m uv run pytest -q -m "slow or not slow"` -> all pass; `python -m uv run ruff check` ->
   `All checks passed!`
9. `python -m uv run pytest -q -m slow tests/test_check_run_script.py` -> passes: `scripts/extract.py` against
   the fake server, then `scripts/check_run.py <run_dir>` as a subprocess -> exit 0 and the DoD line.
10. [COSTS MONEY, ~$0.11 at gemini-3.6-flash list price, or $0 if the M3 response cache is warm (the JSON

## Risks
- False `evidence_not_grounded` on real documents where the model paraphrases its quote -> loose string
  matching, numeric/date matching through the shared normalizer, `description` failures soft only; criterion
  10 reports the real rate; S4 measures the opposite failure (hallucination) later.
- Long invoices (30-60 rows) may lose rows to grounding -> the checker prints abstained row counts; caps and
  threshold are S1's to calibrate. Not loosened here.
- Caps (0.5/0.7/0.85) and `ABSTAIN_BELOW=0.3` are uncalibrated placeholders -> documented as such (like
  `MISMATCH_CONFIDENCE_CAP`), chosen on dev in S1.
- `model_copy(update=...)` does not re-run validators -> `validate_document` builds only schema-valid states
  and tests assert the field/row invariants on its output.
- Confidence must not lower twice (row cap then formula) -> min-based caps are idempotent; tested in
  criterion 5.
- `docextract` must not import `evalkit` -> nothing here reads ground truth; `check_run.py` reads run records
  only.

## Deviations from roadmap
- "Evidence grounding" is self-consistency (value traceable in its own evidence quote + page in range), not
  grounding "against page text" as M3's spec phrased it: the stack has no page text (rasterized pages, no
  OCR), a PDF text sidecar would carry redacted content as text, and OCR is N1. Decided with you.
- "sum of lines ±tax ±discount = total" is implemented as two reconciliations (`lines_ne_subtotal`,
  `components_ne_total`), so a document without printed rows still gets the summary check.
- DoD "every field carries value, confidence, evidence, status and reasons" is true of the schema shape since
  M1; M4 makes confidence meaningful, adds reasons and abstention, and `scripts/check_run.py` turns the DoD
  into a runnable check.
