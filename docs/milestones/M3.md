# M3: Extraction v1

Status: spec (written before code; not edited after approval)
Roadmap ref: docs/ROADMAP.md#M3

## Goal
A document's stored pages go to the model in ONE multi-page call with a real extraction prompt and come back
as a validated `DocumentExtraction` in which every extracted value cites a verbatim quote and a real page, with
malformed output repaired. A runner extracts a whole split (or named documents) and records every document's
outcome without ever crashing on one bad document.

## Scope
- `extract/prompt.py`: the extraction prompt (moved out of `scripts/smoke.py` and extended): pages come in order
  (image 1 = page 1); explicit "status absent + value null if the document does not print it, never guess";
  evidence = verbatim quote + page for every extracted field and row; field definitions consistent with
  `ground_truth/LABELING.md` (document_number incl. booking id / nomor seri faktur, subtotal = DPP, tax = PPN,
  total only if printed as such, line items across all pages). Plus a prompt hash.
- `ingest/stored.py`: `stored_pages(doc_id, pages_dir, *, derived)` returns a document's stored pages in order,
  each checked against its sidecar (`ingest.json`, or `degrade.json` for a variant). Moved from
  `evalkit/prelabel.py`, which keeps its behaviour and messages by delegating.
- Contract check before validation (repairable): an `extracted` field or row with blank evidence or no page, or
  ANY page outside 1..N (N = pages sent), is a problem that triggers a repair. It runs in the preprocess hook next
  to the normalizer (`extraction_preprocess(page_count)`). The client gains `PreprocessResult.violations`,
  reported as-is (not as "could not normalize").
- `extract/extractor.py`: `extract_pages(pages, *, client, settings)` builds the system prompt + one image message
  (all pages in order, `LLM_IMAGE_MAX_LONG_EDGE` applied), calls `chat(DocumentExtraction, preprocess=...)`, and
  returns the raw parsed result and the validated one (`validate_line_items`). More than `LLM_MAX_PAGES` (new
  setting, default 15) pages is refused before any request.
- `extract/runner.py` + `scripts/extract.py`: `--split dev|test` or `--doc ID` (repeatable), `--run-id`,
  `--cache on|off|refresh`, `--dry-run`, path overrides. Runs one document at a time (no concurrency).
  - Writes `outputs/runs/<run_id>/docs/<doc_id>.json` as each document finishes. The record holds the status
    (`ok | failed | refused | not_run`), page files with hashes, raw text, parsed, validated, repair history,
    normalizations, usage, real and cached cost, latency, attempts, structured mode, finish_reason and any error.
  - Writes `outputs/runs/<run_id>/run.json` at the end and on a stop. It holds model, endpoint, prompt hash,
    schema hash, the relevant settings, the selection, per-doc status and totals. It never contains the key.
  - Errors are handled per document:
    - Known failures (`ProviderError` incl. `ResponseParseError` after repairs, missing or tampered pages, too
      many pages) are recorded and the run continues.
    - `BudgetExceededError` stops dispatch: partial results are flushed, the rest are `not_run`, and the exit
      code is 3.
  - Exit codes: 0 all ok, 1 any failed/refused, 2 bad arguments/config/empty selection, 3 cost cap.
- Blind guard (zero requests): a document that is blind, or whose `gt_from` owner is blind, is refused while the
  owner has no finished label in `ground_truth/`.
- `scripts/smoke.py` uses the shared prompt and hook (one prompt, one contract).
- `LLM_MAX_PAGES` in `config.py` and `.env.example`. CLAUDE.md gets the new command, the env var and the blind
  rule, nothing else.

## Acceptance criteria
Offline and deterministic. Mark costly commands [COSTS MONEY] + estimate.
1. `python -m uv run pytest -q tests/test_stored_pages.py` -> all pass. Covers:
   - `ingest.json` and `degrade.json` pages returned in page order;
   - a missing sidecar, a missing page file and a tampered page are each refused with a message naming the doc.
2. `python -m uv run pytest -q tests/test_prelabel.py` -> all pass, and `git diff --quiet HEAD -- tests/test_prelabel.py`
   -> exit 0 (prelabel behaviour unchanged after the move).
3. `python -m uv run pytest -q tests/test_extractor.py` -> all pass. Covers:
   - exactly one request per document, carrying the system prompt and all N stored pages as images in page order
     (bytes match the stored pages), with a json_schema response_format;
   - the prompt contains the null-if-absent and evidence+page instructions;
   - each of these is repaired to a valid result with `repairs == 1` and the failure in `repair_history`:
     (a) invalid JSON, (b) an extracted field with a null value, (c) an extracted field or row without evidence,
     (d) a page > N;
   - output still malformed after `LLM_MAX_REPAIRS` -> `ResponseParseError`;
   - pages > `LLM_MAX_PAGES` -> refused with 0 requests.
4. `python -m uv run pytest -q tests/test_extract_runner.py` -> all pass. It runs a synthetic dev set (a 3-page
   doc, a degraded variant, a doc with no pages, a doc that gets HTTP 500 after retries, a doc still malformed
   after repairs) and checks that:
   - every selected doc gets a record;
   - the failures do not stop the run;
   - the result is exit status 1.

   It also checks that:
   - the cost cap stops the run: the remaining docs are `not_run`, `run.json` has `stopped: "cost_cap"`, exit 3;
   - a blind doc, or a variant of one, without a finished label is refused with 0 requests, and is allowed once
     the label exists;
   - no record contains the API key.
5. `python -m uv run pytest -q -m slow tests/test_extract_script.py` -> passes. It runs `scripts/extract.py --split dev`
   as a subprocess (empty `--env-file`, scrubbed env) against the fake server, over 3 synthetic dev docs with one
   scripted malformed-then-valid reply. Expected:
   - exit 0;
   - stdout has a line starting `done: 3 ok, 0 failed`;
   - `run.json` totals show 3 ok and 1 repair;
   - 3 doc records.
6. `python -m uv run python scripts/extract.py --split dev` (the real manifest, before any network or config) -> exit 2,
   prints `no documents in split 'dev'` (none are assigned yet).
7. `python -m uv run pytest -q -m "slow or not slow"` -> all pass; `python -m uv run ruff check` -> `All checks passed!`
8. [COSTS MONEY, ~$0.30 at gemini-3.5-flash list price, run with `MAX_RUN_COST_USD=1.00` for the process]
   - `python -m uv run python scripts/ingest.py --doc cons_001 --doc cons_002 --doc cons_003`, then
   - `python -m uv run python scripts/extract.py --doc cons_001 --doc cons_002 --doc cons_003`
   - Expected: exit 0, `done: 3 ok, 0 failed`, and every extracted field and row in the 3 records has evidence and
     a page within its document.

## Risks
- Long constructed invoices (30-60 rows) produce long outputs. Truncated output (`finish_reason=length`) is not
  repaired, so that doc fails -> it is recorded with its finish_reason; a token-budget setting belongs to M8.
  Not loosened.
- The stricter contract (evidence + page) costs extra repair calls -> repairs and cost are in every record and in
  the totals; `LLM_MAX_REPAIRS` bounds them.
- Layering: `docextract` must not import `evalkit` (it doesn't today) -> the blind guard checks
  `ground_truth/<doc_id>.json` directly, the same rule as `gt_store.label_path`.
- Moving `stored_pages` could change prelabel behaviour -> criterion 2 (its tests unchanged and green).
- Fake-server tests prove wiring, not model behaviour -> criterion 8 is the only live evidence, and a repair may
  not happen live; the report says so.
- CLAUDE.md holds your uncommitted "Milestone procedure" section -> I stage only my own hunk
  (`git apply --cached` of that hunk); your lines stay unstaged.

## Deviations from roadmap
- DoD "runs on all dev docs": the dev split is empty (no doc_type/split on real docs, nothing ingested). Met by a
  synthetic dev set offline (criteria 4-5) and the 3 constructed invoices live (criterion 8). The run on the real
  dev set waits for M2's human steps.
- "JSON-schema output, Pydantic validation, retry on malformed output" were already built in M1.1. M3 wires them
  into the document-level extractor and tests them there.
- "Multi-page VLM call" is capped at `LLM_MAX_PAGES` (15): `doc_017` (78 pages) and `doc_010` (20) need
  `page_range` rows first.
